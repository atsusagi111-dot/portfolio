# デプロイ手順（ConoHa WING）

このサイトは **静的エクスポート** で運用します。`npm run build` で生成される `out/` フォルダの中身を、
ConoHa WING の公開フォルダへアップロードするだけで公開できます（サーバー側で Node.js は不要です）。

## 0. 初回だけ行う準備

### 0-1. ConoHa WING 側

1. コントロールパネル →「サーバー管理」→「ドメイン」で、本番ドメイン（【後で指定】atsusagi-lab.◯◯）を追加する
2. 「サイト管理」→「サイトセキュリティ」→ **無料独自SSL** を「利用設定 ON」にする（反映まで最大1時間ほど）
3. 「メール管理」で、お問い合わせフォームの送信元にするメールアドレスを作成する（例：`info@ドメイン`）
4. 「サイト管理」→「サイト設定」→「応用設定」で PHP のバージョンが 8.x になっていることを確認する
5. 「サイト管理」→「FTP」で FTP アカウントを作成する（接続先ディレクトリは `public_html/ドメイン名/`）

### 0-2. お問い合わせフォームの設定

`public/contact/config.php` の 2 か所を書き換えます。

```php
'to'   => '受信したいメールアドレス',
'from' => 'ConoHaで作成した独自ドメインのメールアドレス',
```

> 送信元（from）を Gmail などの外部アドレスにすると、迷惑メールに入りやすくなります。必ず独自ドメインのアドレスにしてください。

### 0-3. 本番ドメインの設定

プロジェクト直下に `.env.local` を作成し、本番ドメインを書きます（末尾のスラッシュなし）。

```
NEXT_PUBLIC_SITE_URL=https://【後で指定】
```

この値は canonical・OGP・sitemap.xml・robots.txt・RSS・構造化データに反映されます。
**未設定のままビルドすると `https://example.com` になる**ので、公開前に必ず設定してください。

## 1. ビルド

```bash
npm install      # 初回、または package.json が変わったとき
npm run build    # out/ が生成される（画像の最適化も自動で実行される）
```

## 2. ローカルで最終確認

```bash
npm run preview  # http://localhost:3000 で out/ を配信
```

- 各ページの表示、ヘッダーのタブ遷移、URL直接入力、リロードを確認する
- お問い合わせフォームの**送信**はローカルでは確認できません（PHPが動かないため）。アップロード後に本番で確認します

## 3. アップロード（手動）

### 方法A：ファイルマネージャー（ブラウザだけで完結）

1. コントロールパネル →「サイト管理」→「ファイルマネージャー」を開く
2. `public_html/ドメイン名/` を開く
3. `out/` フォルダの**中身をすべて**（フォルダごとではなく中身を）アップロードする

### 方法B：FTPソフト（FileZilla / WinSCP など）

1. 0-1 で作成した FTP アカウントで接続する（FTPS 推奨）
2. `out/` の中身を `public_html/ドメイン名/` へアップロードする

### 注意

- **`.htaccess` は隠しファイル**です。エクスプローラーで「隠しファイルを表示」にして、アップロード漏れがないか確認してください
- `_next` フォルダも必ずアップロードしてください（CSS・JavaScript が入っています）
- 更新時は上書きアップロードで構いません。`_next/static/` には古いファイルが残りますが、害はありません（気になる場合は `_next` フォルダを削除してからアップロード）
- ConoHa WING が最初から置いている `index.php` や `default.html` などが公開フォルダにあれば削除してください（`index.html` より優先されることがあります）

## 4. 公開後のチェックリスト

- [ ] `http://ドメイン/` が `https://ドメイン/` にリダイレクトされる
- [ ] `https://ドメイン/services/` など各ページに直接アクセスでき、リロードしても表示される
- [ ] `https://ドメイン/services`（末尾スラッシュなし）でも表示される
- [ ] 存在しないURL（例：`/abc/`）で 404 ページが表示される
- [ ] お問い合わせフォームからテスト送信し、①運営者宛の通知メール ②自動返信メール が届く（迷惑メールフォルダも確認）
- [ ] `https://ドメイン/contact/config.php` にアクセスすると 403（閲覧禁止）になる
- [ ] `https://ドメイン/sitemap.xml` と `/robots.txt` の URL が本番ドメインになっている
- [ ] Google Search Console にサイトを登録し、sitemap.xml を送信する
- [ ] 上記がすべて確認できたら、旧サイト（Vercel）を停止する（Vercel の管理画面 → プロジェクト `portfolio` → Settings → Delete Project。2026-09-21 決定）

### うまくいかないとき

| 症状 | 原因と対処 |
|---|---|
| 500 Internal Server Error | `.htaccess` の記述がサーバーに合っていない可能性。`.htaccess` を一時的に外して表示されるか確認し、ブロック単位で戻して原因を特定する |
| リダイレクトが無限ループする | `.htaccess` の「HTTPS を強制」ブロックを削除し、代わりに ConoHa の管理画面のSSL設定でHTTPSへの転送を有効にする |
| フォーム送信でエラーになる | `config.php` のメールアドレスが未設定（【後で指定】のまま）／PHP のバージョンが古い（8.x にする） |
| メールが届かない | 送信元が独自ドメインのアドレスになっているか確認。迷惑メールフォルダも確認する |
| デザインが崩れる（CSSが当たらない） | `_next` フォルダのアップロード漏れ |

## 5. 自動デプロイ案（GitHub Actions）

`main` ブランチへ push すると、GitHub 上でビルドして ConoHa WING へ FTP アップロードする構成です。
ワークフローのひな形を `docs/github-actions-deploy.yml.example` に用意しています。

### 導入手順

1. `docs/github-actions-deploy.yml.example` を `.github/workflows/deploy.yml` としてコピーする
2. GitHub のリポジトリ →「Settings」→「Secrets and variables」→「Actions」で次を登録する

   | 種類 | 名前 | 値 |
   |---|---|---|
   | Secret | `FTP_SERVER` | ConoHa の FTP サーバー名 |
   | Secret | `FTP_USERNAME` | FTP ユーザー名 |
   | Secret | `FTP_PASSWORD` | FTP パスワード |
   | Variable | `SITE_URL` | `https://本番ドメイン` |

3. `config.php` のメールアドレスをリポジトリに含めたくない場合は、`config.php` をサーバーに手動で置き、ワークフローの `exclude` に追加する（ひな形に記載済み）

### 注意

- 現在このリポジトリは Vercel と連携しており、`main` への push で Vercel にも自動デプロイされます。ConoHa へ移行後は、Vercel 側をプレビュー用として残すか、連携を解除するかを決めてください
- FTP は初回に全ファイルをアップロードするため数分かかります。2回目以降は差分のみです
- より高速・安全にしたい場合は、ConoHa WING の SSH を有効にして rsync でアップロードする方法もあります（SSH鍵の登録が必要）
